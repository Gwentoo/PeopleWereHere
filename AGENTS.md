# AGENTS.md — постоянные инструкции для Codex / Claude Code

Ты разрабатываешь **локальную одиночную браузерную игру о возрождении цивилизации**. Читай `docs/CONCEPT.md` как главный источник игрового замысла, а также спецификации по текущей задаче. Если есть конфликт — сначала укажи его пользователю; не переопределяй замысел молча.

## Непреложные ограничения
- Стек: **Go** (детерминированное ядро), **React + TypeScript + Vite** (UI), **SQLite** (локальные сохранения, на соответствующем этапе). Python — только офлайн-аналитика.
- Только **localhost**, одиночная партия. Не добавляй регистрацию, мультиплеер, облако, микросервисы, Redis, очереди, Docker как обязательное условие.
- Не делай пошаговую игру: симуляция течёт по внутренним тикам независимо от действий, пауза и скорость изменяются отдельно.
- Прогресс **не привязан к годам**. Современные люди восстанавливают известные им технологии, реальными ограничителями служат знания, материалы, производственные возможности, организация и случайность.
- Ресурсы обобщены, нет склада на каждый минерал; находка жилы — информационное/технологическое событие, а не генератор «железа в секунду».
- Рождение детей и сложная демография не входят в текущую версию. Возраст героя при пробуждении 20 лет; игра заканчивается **только смертью героя**.
- Значимые NPC индивидуальны, массовое население агрегировано; с ростом населения ручные действия постепенно автоматизируются.
- Много атмосферных сообщений, но мало обязательных выборов. Критические события автоматически ставят паузу.
- Один и тот же seed + те же решения в те же игровые моменты + та же версия правил/контента = одинаковый результат. Не используй глобальный рандом или wall-clock внутри ядра.

## Рабочий процесс
1. Реализуй **только** запрошенную стадию из `docs/07_IMPLEMENTATION.md` и `docs/08_CODEX_TASKS.md`.
2. Перед изменениями кратко изложи план и затрагиваемые файлы; после — перечисли изменения, запущенные команды и результаты тестов.
3. Для новых правил добавляй тесты, используй `go fmt`/`go test ./...`, для интерфейса — `npm run build` и доступные тесты.
4. Держи игровую логику независимой от HTTP, SQLite, UI и реальных таймеров.
5. Стремись к **простым пакетам и функциям**, не к архитектуре ради архитектуры. Не создавай фиктивные интерфейсы и зависимости без необходимости.
6. Запрещено выдавать заглушку за готовую механику. Если часть работы не сделана, явно пометь и опиши в README.
7. Все важные настройки баланса выноси в версионируемый конфиг; записывай принятые допущения в `docs/09_DECISIONS.md`.
8. Не удаляй и не перезаписывай пользовательские файлы, не выполняй опасные команды вне репозитория без подтверждения.
9. Работай небольшими проверяемыми шагами, сохраняй существующие работающие сценарии.

## Приоритеты
**Играбельность и качество цикла > воспроизводимость и тестируемость > полнота контента > оформление.** Концепция определяет направление; точные числа задаются пробно и корректируются тестами, а не выдумываются как окончательные.
