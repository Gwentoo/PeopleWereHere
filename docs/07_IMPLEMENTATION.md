# 07 — Порядок реализации: короткие проверяемые стадии

> **Одна стадия = один отдельный запрос Codex**, ревью кода, проверка и Git-коммит. Не реализовывать всё заранее. Этапы 0–2 должны быстро дать минимальную живую игру в браузере.

## Общий Definition of Done для каждой стадии

- Новые возможности **работают**, а не только описаны в README.
- Есть тест на ключевое правило/сценарий, подходящие команды выполняются.
- Документация запуска актуальна; новые допущения занесены в `docs/09_DECISIONS.md`.
- Не создана инфраструктура, не нужная для текущего этапа.
- В конце агент сообщает затронутые файлы, как запускать, какие тесты выполнены и какие ограничения остаются.

## Этап 0. Основа репозитория

**Задача:** создать каркас Go и React без избыточной архитектуры; сделать простую страницу и локальный endpoint `health`.

- Go module, `cmd/server`, HTTP bind к `127.0.0.1:8080`, endpoint `GET /api/health`.
- `web/` на React + TypeScript + Vite, настройка dev proxy на Go.
- README с PowerShell-командами запуска из GoLand.
- Пустая заглушка UI допустима **только на этом этапе**.

**Приёмка:** Go запускается, Vite открывается, запрос с UI к health успешен, `go test ./...`, `npm run build` проходят.

## Этап 1. Детерминированный core

**Задача:** первый полноценный `GameState`, `Step`, `ApplyCommand`, seed, базовые тесты.

- Стартовые данные: герой 20 лет, 3 характеристики, население 1, игровой день 0, стартовое дерево, статуи/сок/ёмкость, базовое обеспечение.
- Команды: хотя бы `start_task`, `revive` (валидировать невозможные значения), `set_speed` остаётся функцией оболочки.
- Первый тип задачи: поиск статуй/исследование окружающей области, работающая задержка до завершения.
- Один или два сообщения о произошедших событиях, одинаковые при повторении с seed.

**Приёмка:** headless Go-тест прогоняет 1000 игровых дней без UI; два повтора с одинаковыми командами дают идентичное состояние; ограничения сока/статуй соблюдены.

## Этап 2. Первое живое браузерное прохождение (вертикальный срез)

**Задача:** подключить реальный Go-core к основному экрану.

- Новая игра с seed и режимом характеристик, текущий день/возраст, статус NPC/сока/населения.
- Поток времени, пауза, ускорения, активные задачи с прогрессом, чат с событиями.
- Действия через API: поиск и пробуждение N; переход в действие не должен автоматически продвигать время.
- Системная остановка при демонстрационном критическом событии с осмысленным выбором, который меняет состояние.

**Приёмка:** за несколько реальных минут можно без консоли играть в браузере: запустить поиск → дождаться результата → пробудить людей → увидеть сообщения → поставить паузу → возобновить; никаких «следующий ход».

## Этап 3. Население, автоматизация, мир

**Задача:** перейти от 1 человека к обществу без роста микроменеджмента.

- Несколько запоминающихся первых NPC с именами/обобщёнными навыками.
- Массовые пробуждения со сводкой, автоматическое пробуждение как политика.
- Автоматическое исследование/сбор сока при достаточной организации, деревья с постоянной скоростью, лимиты хранилища, пригодные статуи.
- Простейшая модель пищи/производства/благополучия без отдельных видов минералов.
- Тест на отсутствие переполнения, массовые пробуждения и самостоятельность без нажатий.

**Приёмка:** с ростом населения можно управлять только приоритетами; мир продолжает развиваться, не нужно запускать десятки экспедиций вручную.

## Этап 4. Технологии, озарения и знания

**Задача:** добавить научный цикл (сначала 8–12 технологических узлов, затем расширять).

- Загрузка описаний узлов из конфигурации, валидатор DAG.
- Разделение теории и практической доступности; исследования идут фоном.
- Зависимости от производства, знаний, озарений; личный вклад NPC и сохранённые записи/обучение.
- Небольшой UI-список/дерево с прогрессом; приоритеты.

**Приёмка:** технология не открывается лишь потому, что прошёл год; может осваиваться быстро при удачных условиях; книги помогают сохранить бонус после смерти NPC.

## Этап 5. События и культура

**Задача:** перейти от прямолинейной симуляции к историям.

- Загрузка событий из данных, eligibility/weight/cooldown, истории, три уровня важности.
- Хотя бы один длительный процесс с последствиями, например засуха.
- Инициативы NPC и органические культурные тенденции; первые институты (школа/совет/архив).
- Лента становится насыщенной, большая часть сообщений не требует выбора.

**Приёмка:** два seed порождают разные истории; критический выбор блокирует время; обычное событие нет; имя конкретного NPC/поселения сохраняется в дальнейших сообщениях.

## Этап 6. Карта и масштабирование UX

**Задача:** связать пространственный контекст и прогресс, не делать отдельную стратегию.

- Узнаваемый схематичный мир/континенты, открытие областей, ограничение водных путешествий до транспорта.
- Метки деревьев, поселений, статуй, неопознанных находок; позднее уменьшение детализации.
- Клик по поселению → основание, жители, специализация, история.
- Меню раскрывающихся категорий и 2–3 рекомендации; автоматизация рутины.

**Приёмка:** можно через чат прочесть «найдена жила», увидеть метку, позднее получить озарение и обновлённое описание; карту не нужно использовать для производства.

## Этап 7. Возраст, смерть, финал, сохранения

**Задача:** сделать партию законченной и сохраняемой.

- Непредвзятая, конфигурируемая модель старения/здоровья и смерти героя, без обязательного возраста смерти.
- Финал со статистикой, именами героев, ключевыми событиями, seed и текстовым эпилогом.
- SQLite (или промежуточный совместимый snapshot), загрузка state/RNG/истории/ожидающих решений.
- Проверка сохранения при системной паузе, воспроизведения seed/команд.

**Приёмка:** можно закончить партию по смерти, получить целостный отчёт, сохранить и продолжить без изменения будущего при одинаковых действиях.

## Этап 8. Баланс, массовые симуляции, улучшения

**Задача:** расширить контент до планового количества и исправить реальные перекосы.

- Консольный simrunner с политиками автоигрока и защитной отсечкой (`censored`, не смерть).
- JSONL результаты и Python-отчёт; репродукция плохих seed.
- Расширение технологий/событий по `03_CONTENT.md`, разнообразие атмосферных сообщений.
- Ручные тесты скорости реального прохождения и качества интерфейса.

**Приёмка:** запускаются тысячи симуляций, строится отчёт, известны закономерности баланса; живой игрок может провести полноценную разнообразную партию.

## Чего не должно быть в первых этапах

- Многопользовательского backend, авторизации, web-hosting.
- Псевдоготовой карты мира раньше рабочего игрового цикла.
- Сотен событий до отладки системы событий.
- Идеально настроенного баланса до получения массовых данных.
- Избыточного числа Go-пакетов, когда реальных правил ещё нет.

## Принцип перераспределения задач

Если этап получается слишком крупным, агент **делит только текущий этап на 2–3 проверяемые подзадачи**, согласовывает критерии проверки и не начинает следующий этап автоматически.
