# 08 — Последовательные запросы для Codex / Claude Code

> Инструкция: открыть репозиторий с этими документами; в новом чате агента **отправлять один запрос за раз**. Это конкретные задания, не один промпт на всю игру. Перед каждым этапом коммитить предыдущий рабочий результат.

## Универсальное правило для каждого запроса

Агенту уже доступны `AGENTS.md` и `docs/`. В конце каждого задания требовать: фактический список изменений, запуск `go test ./...` и frontend build, способ ручной проверки, открытые вопросы; если тест не запускался — явно сообщить. Код/текст в GUI должен быть на русском, если это интерфейс игры.

## Задача 0 — скелет (отправить первой)

```text
Прочитай AGENTS.md, README_START_HERE.md, docs/CONCEPT.md, docs/04_ARCHITECTURE.md, docs/07_IMPLEMENTATION.md и docs/09_DECISIONS.md. Сначала кратко перечисли ограничения, которые нельзя нарушать. Затем реализуй только ЭТАП 0 из docs/07_IMPLEMENTATION.md: локальный Go HTTP-сервер на 127.0.0.1, /api/health, React + TypeScript + Vite, Vite proxy, простой UI с проверкой подключения. Не добавляй симуляцию, БД, регистрацию, Docker или лишние библиотеки. Напиши README с конкретными PowerShell-командами запуска из GoLand. Запусти доступные тесты и сборку, укажи результат и изменения. Если не можешь скачать зависимости, подготовь рабочие файлы и честно напиши, что не смог проверить.
```

**Ручная проверка:** из двух терминалов локально стартуют API и Vite, видна страница с состоянием подключения.

## Задача 1 — ядро

```text
Прочитай AGENTS.md, docs/01_GAME_RULES.md, docs/02_SIMULATION.md и этап 1 docs/07_IMPLEMENTATION.md. Реализуй только ЭТАП 1: GameState с героем 20 лет и характеристиками, seed/RNG, Step на один игровой день, ApplyCommand, накопление сока с фиксированной скоростью дерева и ограничением резервуара, пригодные статуи, поиск как задача с длительностью, массовое пробуждение по числу N. Исключи wall-clock и HTTP из core. Добавь unit-тесты на инварианты и детерминизм. Не делай на этом этапе полное дерево технологий, культуру, карту, сохранения или десятки событий. Запусти go test ./... и кратко объясни API ядра.
```

**Ручная проверка:** тест создаёт мир и шагами получает находку/пробуждение без реального времени.

## Задача 2 — браузерный вертикальный срез

```text
Прочитай AGENTS.md, docs/04_ARCHITECTURE.md, docs/05_UI_UX.md, docs/02_SIMULATION.md и этап 2 docs/07_IMPLEMENTATION.md. Реализуй только ЭТАП 2: реальный Go-core под локальным HTTP API, новая партия с вводом seed, течение времени без кнопки «следующий ход», пауза и скорость, актуальный snapshot и поток/обновление событий, основная лента на русском, базовые статусы, поиск/пробуждение N, прогресс активной задачи. Добавь одно демонстрационное критическое событие с решением и системной паузой. API должен валидировать команды, UI не должен хранить собственную «истину» о населении и соке. Не добавляй большую карту/технологии. Проверь Go тесты, сборку web и пройди сценарий вручную.
```

**Ручная проверка:** создать → включить ×4 → поиск завершается через время → появляется сок → пробудить → критическое событие останавливает время.

## Задача 3 — население и мир

```text
Прочитай AGENTS.md, docs/01_GAME_RULES.md, docs/02_SIMULATION.md, docs/03_CONTENT.md и этап 3 docs/07_IMPLEMENTATION.md. Расширь работающую игру только до ЭТАПА 3: именованные первые NPC с общими компетенциями, групповые отчёты при массовом пробуждении, автоматизация разведки/сбора сока/пробуждения по приоритетам, дерево с постоянной скоростью, хранилище с потерей переполнения, пригодность статуй, простые обобщённые пища/производственный потенциал/благополучие. Учитывай масштабирование без ручного назначения каждой экспедиции. Не добавляй отдельные запасы железа, меди, угля. Добавь тесты и обнови интерфейс минимально необходимым образом.
```

**Ручная проверка:** с увеличением населения можно перестать вручную искать/пробуждать, игра растёт самостоятельно.

## Задача 4 — технология и озарение

```text
Прочитай AGENTS.md, docs/01_GAME_RULES.md, docs/02_SIMULATION.md, docs/03_CONTENT.md и этап 4 docs/07_IMPLEMENTATION.md. Реализуй ЭТАП 4 небольшим полнофункциональным срезом из 8–12 технологий, а не сразу всеми 36. Каждому узлу нужны ID, зависимости, теоретический прогресс, практическая доступность, базовые усилия, условия производства; добавь озарения от NPC/находок, сохранение части бонуса в записях или обучении, не удаляй завершённые технологии при смерти NPC. Убери любые «откроется только на N-й год». Позволь задавать научные приоритеты, сделай простой обзор исследований в браузере. Валидируй DAG и невозможные зависимости. Покажи в тестах, что ранняя металлообработка может быть открыта быстро при хорошем старте, а реактор нельзя создать только из знания его принципа.
```

**Ручная проверка:** видно исследование, теорию/практику и ограничения; знание не равно готовому оборудованию.

## Задача 5 — события и культура

```text
Прочитай AGENTS.md, docs/02_SIMULATION.md, docs/03_CONTENT.md, docs/05_UI_UX.md и этап 5 docs/07_IMPLEMENTATION.md. Реализуй ЭТАП 5: загрузка небольшого каталога из 8–12 событий, условия/веса/cooldown, info/optional/critical, один настоящий длительный процесс с несколькими исходами, инициативы важных NPC, 2–3 института культуры и несколько органически возникающих тенденций. События и история должны ссылаться на реальные stable ID NPC и поселений. Добавь несколько атмосферных сообщений без обязательных решений, при этом не повторяй одно и то же бесконечно. Не моделируй каждую эмоцию тысячи жителей. Прогони тесты критической паузы, cooldown и детерминизма.
```

**Ручная проверка:** не каждое сообщение кликабельно; если есть критическое решение, время остановлено; NPC помнятся.

## Задача 6 — карта и удобство интерфейса

```text
Прочитай AGENTS.md, docs/05_UI_UX.md, docs/01_GAME_RULES.md и этап 6 docs/07_IMPLEMENTATION.md. Реализуй только ЭТАП 6: компактная карта с узнаваемыми материками/океанами, туманом знания и редкими метками (деревья, статуи, важная руда, поселения). По клику на поселение видны основание, население, специализация и значимые события. Отдельные рудные жилы не создают ресурсный склад. Добавь раскрывающиеся категории действий, 2–3 контекстные рекомендации и сокрытие второстепенных меток в большой цивилизации. Не превращай карту в стратегическую мини-игру и не добавляй управление каждой экспедицией.
```

**Ручная проверка:** находка в чате отражается на карте, метка меняется после опознания.

## Задача 7 — смерть, сохранения, финал

```text
Прочитай AGENTS.md, docs/02_SIMULATION.md, docs/04_ARCHITECTURE.md, docs/05_UI_UX.md и этап 7 docs/07_IMPLEMENTATION.md. Реализуй ЭТАП 7: возраст 20+ и конфигурируемая модель здоровья/рисков/смерти без фиксированного возраста окончания, завершение игры только по смерти героя, детерминированный итог/эпилог с важными именами и событиями. Добавь локальные сохранения SQLite с восстановлением состояния RNG, версии контента, истории и ожидающего обязательного решения. Сохранение не должно требовать онлайн-сервиса. Добавь тест, что сохранённая и затем продолженная партия совпадает с непрерывной при тех же действиях.
```

**Ручная проверка:** сохранить/закрыть/загрузить; после смерти больше нет тиков; итог соответствует истории.

## Задача 8 — массовые симуляции и баланс

```text
Прочитай AGENTS.md, docs/06_TESTING.md, docs/07_IMPLEMENTATION.md, docs/03_CONTENT.md и этап 8 docs/07_IMPLEMENTATION.md. Реализуй ЭТАП 8: CLI simrunner, несколько воспроизводимых политик автоигрока, прогон 1000/10000 независимых партий без UI и sleep, JSONL статистика, Python анализ распределений, пометка censored при технической отсечке. Сравни минимум 2 стратегии по населению, возрасту смерти, технологиям, числу критических решений и частоте событий. Найди минимум 3 конкретных проблемных seed и предложи небольшие корректировки конфигурации баланса. Не подгоняй технологические сроки под фиксированные годы, не обещай 50–60 минут без ручного playtest.
```

**Ручная проверка:** массовый прогон выполняется; отчёт показывает реальные данные и воспроизводимые seed.

## Универсальный запрос на ревью после каждого этапа

```text
Проведи ревью только изменений последнего этапа. Сверь код с AGENTS.md и docs/CONCEPT.md. Найди логические нарушения правил, баги детерминизма, проблемы тестов и ненужное усложнение. Не реализуй следующую стадию. Исправь критичные ошибки и покажи итоговый diff/список файлов и выполненные тесты.
```

## При ошибке или нежелательном усложнении

```text
Остановись. Не добавляй новые механики. Объясни, какое конкретно правило из docs/CONCEPT.md или текущей стадии нарушено, исправь только его, добавь регрессионный тест и сохрани работоспособность браузерного вертикального среза.
```
