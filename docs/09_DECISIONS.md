# Решения, предположения и открытые параметры

## A. Утверждено в обсуждении

- Одиночная браузерная игра, история одного основателя; смерть героя завершает партию.
- Ориентир 50–60 минут реального времени на полноценное прохождение, возможны короткие партии; **не убивать героя по таймеру**.
- Герою 20 биологических лет при пробуждении, по умолчанию 3700 лет после окаменения.
- 3 характеристики 0–10 с дефолтом 5/5/5 и **свободным** режимом настройки без общего лимита.
- Можно указать seed; начальная география приблизительно соответствует Земле, место статуи могло сместиться.
- Деревья растут/производят сок с постоянной собственной скоростью (в смысле скорость выработки постоянна), не ускоряются наукой; сок в дереве не хранится, в хранилищах есть предел, сок не портится.
- Пробуждение числом людей, ранние NPC индивидуальны, позднее массовые сводки; отдельные выдающиеся NPC остаются важными.
- Нет естественного прироста населения в базовом замысле.
- Нет микроменеджмента городов, экспедиций и тонкого учёта сырья; примерно после 30–50 жителей рутинное исследование может автоматизироваться.
- Наука: дерево, озарения, разделение теории/практики, сохранение знаний и книги, быстрый прогресс без временных ворот.
- Культура: **гибрид** доступных институтов и органически возникающих особенностей, без обязательной шкалы авторитета.
- Реальное время симуляции непрерывно, внутренний дискретный тик, скорости/пауза, события могут требовать решения.
- Много необязательных сообщений в единой ленте, 2–3 рекомендации, компактные раскрывающиеся действия.
- Карта вспомогательная, материки узнаваемы, меток немного; поселения открывают карточку с датой, населением, профилем и историей; нет обязательных руин и карты опасных зон.
- Нужны воспроизводимые партии, сохранения и массовые симуляции для подбора баланса.

## B. Инженерные решения текущей версии (можно пересмотреть)

- Go + React/TypeScript/Vite; Go локально обслуживает API и статику; локальный SQLite для сохранений.
- Внутренний тик — **один игровой день**; это технический шаг, не длительность сообщения/действия. Для ускорения можно батчить дни, но не пропускать проверки важных событий.
- Однопроцессный Go-монолит. HTTP слушает исключительно `127.0.0.1`.
- Browser получает поток сообщений через SSE, действия отправляются через HTTP; при необходимости допускается короткий polling без изменения ядра.
- Для первого вертикального среза допустим простейший интерфейс без законченной карты.
- Контент в версионируемых JSON (или эквивалентном формате с явной схемой); не подключать LLM для событий.

## C. Не определено окончательно — настраивать по результатам тестов

- Производительность дерева: доз/игровой день; темп открытия деревьев и количество сохранившихся статуй.
- Стоимость пробуждения, ёмкость хранилищ, скорость роста населения.
- Продолжительности и стоимость технологий; коэффициенты озарений; параметры образования и сохранения знаний.
- Темпы развития и специализации общества, распространения культуры, благополучие, продовольственный баланс.
- Влияние характеристик игрока, вероятности редких NPC и событий.
- Базовые шансы смерти/болезни, воздействие медицины, риски экспедиций и действий.
- Конкретное соответствие скоростей ×1/×2/×3/×4/×8/×12 игровым дням в секунду.
- Состав и точное число технологий и сценариев, целевые распределения концовок.

## D. Что сейчас сознательно не делать

- Сервер на большое количество пользователей, авторизация, облачные сохранения, мультиплеер.
- Система рождения детей, полноценная демографическая модель.
- Производственная цепь каждого минерала, справочник всех профессий и наук.
- Руины как самостоятельная механика, детальная география/ГИС и управление экспедициями на поздних этапах.
- Реальное экономическое планирование с десятками складов, сверхдетализированная политика.

## E. Правило разрешения спорных деталей

Если в спецификациях встречается конкретное число, помеченное «пример», «стартовый конфиг», «пилотный коэффициент», оно **не является геймдизайнерским требованием**. Агент должен обеспечить возможность его настройки, а затем проверять распределения на симуляциях. Не задавать обязательные «металл через 3 года» или «электричество через 20 лет».
